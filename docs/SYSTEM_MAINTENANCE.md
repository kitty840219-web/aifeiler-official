# 系統維護文章自動更新

最新文章新增獨立「系統維護」分類，維護紀錄不混入「全部文章」。維護列表只顯示置中的小字標題，日期保留於全文與排序資料。既有語錄、影片與服務文章不更動。

## 自動發布

- `npm run build` 前執行 `scripts/generate-maintenance-articles.mjs`。
- 從目前正式分支可追溯的 Git 紀錄，整理最近一年內的新工具、功能更新與系統維護。
- 用提交的原始日期換算 `Asia/Taipei`，同一天合併一篇，依日期由新到舊顯示。
- 每次官網更新發布時重新產生；每日台灣時間 02:00 的排程也會重建最近一年範圍。排程實際開始時間由 GitHub 決定。
- 沒有新修改的日期不產生文章。純語錄／影片資料、文件及原始 eSIM 展示專案不納入。
- GitHub Actions 取得完整提交歷史（省略歷史圖片 blob），避免淺層 checkout 遺漏更新。
- 每日固定 ID，重跑不會新增重複文章；同日新修改會補進原日文章。

## 歷史補登與內容修訂

- `lib/data/maintenanceNotes.json` 是逐日核實的中文摘要，`coveredCommits` 對應已整理的提交。
- `lib/data/systemMaintenance.json` 是產生結果，供網站靜態建置匯入；正式發布時會重新產生。
- 新提交依改動檔案自動辨識功能範圍，產生中文更新摘要。若要更精確描述新工具的操作，可在 `maintenanceNotes.json` 補充當日內容。
- 未實作或外部平台未完成的功能不得寫成上線；歷史摘要是當日紀錄，不代表目前所有畫面仍維持舊版本。
- 只涵蓋這個官網儲存庫；未提交到此處的其他專案／外部工具不會被偵測。

本機需完整 Git 歷史：`git fetch --unshallow`（只在淺層 clone 需要）。

檢查：`npm run test:maintenance`。
